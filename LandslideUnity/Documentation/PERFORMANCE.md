# 冲撞阶段运行性能实测

## 路线 A 分块网格优化（2026-11-17）

在 Unity 2022.3.62f3c1、NVIDIA GeForce RTX 3050 Ti Laptop GPU、Windows x64 Mono Player 上，用同一 1280×720 离屏相机回放失稳后 10–24 s。每版先预热 60 帧，再采样 480 帧；关闭垂直同步和帧率上限。计时包含滑体、房屋、树木和碎屑更新以及 `Camera.Render`，不含 PNG/视频编码和交互 HUD。三个阶段依次使用单元独立顶点、块内共享顶点、最终路线 A；最终版跳过重合的闭合缝几何计算并压缩可见三角形索引，还把源区碎土出生点对齐块缝。原始 `h/UX/UZ/Bed` 数值文件不变。

| 指标（ms） | 按单元重复顶点 | 块内共享顶点 | 最终路线 A |
|---|---:|---:|---:|
| 脚本更新中位 / P95 | 24.846 / 30.196 | 17.990 / 25.470 | 15.728 / 23.129 |
| 滑体更新中位 / P95 | 23.067 / 28.787 | 16.221 / 23.815 | 13.947 / 21.334 |
| 块体变形中位 / P95 | 10.587 / 11.127 | 3.977 / 4.244 | 4.001 / 4.342 |
| 裂缝生成及上传中位 / P95 | 5.033 / 5.847 | 5.082 / 5.987 | 3.298 / 4.103 |
| 相机渲染提交中位 / P95 | 12.301 / 15.330 | 12.092 / 16.045 | 12.552 / 15.407 |
| Player 帧间隔中位 / P95 | 38.213 / 45.950 | 31.119 / 40.357 | 29.344 / 36.973 |

示例时刻的 2,389 个活动单元原需 9,556 个独立角点；块内共享后为 3,514 个顶点，减少约 63.2%。块体变形的中位耗时减少约 62.4%；随后对重合的闭合缝跳过侧壁几何计算，仅提交可见缝壁的三角形索引，挤压错台仍保留侧壁。裂缝顶点、法线和切线缓冲仍按完整容量上传。共享顶点关键帧与去重前逐像素比对，209、384、474、719 帧的平均灰度差均低于 0.001（8 位灰度取值范围 0–255）；包含降雨的第 0 帧差值约 0.48。三阶段脚本更新中位耗时依次为 24.846、17.990、15.728 ms；最后一阶段比第一阶段减少约 36.7%。

三阶段汇总已归档为 [重复顶点](Performance/route_a_repeated_vertices_summary.json)、[共享顶点](Performance/route_a_shared_vertices_summary.json) 和 [最终版](Performance/route_a_final_summary.json)；最终版的[逐帧总耗时](Performance/route_a_final_frames.csv)、[组件耗时](Performance/route_a_final_components.csv)、[表面分段耗时](Performance/route_a_final_surface_stages.csv)也已保留。播放器以 `--benchmark-dir <输出目录>` 重新采样。帧间隔还含操作系统调度，`Camera.Render` 是 CPU 侧提交与等待，未隔离 GPU 耗时。该离屏基准不能保证任意硬件、窗口大小或交互界面的帧率；影片 30 fps 仅为导出规格。

## 早期物理回放优化（2026-11-06）

测量日期：2026-11-06。Unity 2022.3.62f3c1，NVIDIA GeForce RTX 3050 Ti Laptop GPU，Windows x64 Mono Player。

基线为升级前保留的项目；新版增加体积侧缘、分级房屋、22 棵重点树及 276 个大块运动学碰撞体。两者使用同一 1280×720 离屏相机、相同失稳后 10–24 秒轨迹，各采样 480 帧，先预热 60 帧。关闭垂直同步与帧率上限，计时循环没有 PNG 编码、视频编码或 IMGUI；GPU 型号见 JSON。

| 项目（ms） | 基线中位 | 新版中位 | 基线 P95 | 新版 P95 | 基线最大 | 新版最大 |
|---|---:|---:|---:|---:|---:|---:|
| 脚本更新 + 一次变换同步 | 5.346 | 3.535 | 5.934 | 5.783 | 9.749 | 6.758 |
| 相机渲染提交（CPU 侧） | 1.212 | 1.150 | 1.729 | 1.397 | 4.313 | 1.829 |
| Player 帧间隔 | 9.034 | 6.940 | 10.552 | 9.312 | 18.473 | 11.251 |

脚本更新中位耗时下降约 33.9%；P95 的差异较小，不据此宣称显著改善极端负载。最大值来自单次受控采样，会受机器调度影响。这里未单独测量 GPU 纯渲染耗时；Camera.Render 的计时是 CPU 侧提交/等待，Player 帧间隔还含调度和物理更新。不能把 30 fps 视频导出规格当作实时性能，也不能用这份离屏结果保证所有硬件、全屏分辨率或交互 GUI 的帧率。

## 实施内容

- 测量基线后，滑体改为缓存拓扑和活动顶点（约 2500–6000 个），替代每帧处理全部 29400 个顶点；只在仿真时间改变时更新。
- 背景森林保持静态，重点树单独处理；暂停及重复状态跳过更新。
- 新版保留 277 个 Collider（含地形）和 276 个运动学 Rigidbody；大墙/屋顶保留碰撞，细门窗和尘土不增加碎屑碰撞体。
- 运动学碎片按缓存路径回放，不进行碎屑互撞求解；稳定残骸冻结到稳定姿态并调用 Sleep。少数屋顶角片速度超过 6 m/s 才使用 Continuous Speculative，其余 Discrete。
- 禁用自动 Transform 同步，测量中在所有变换更新后统一 SyncTransforms。

这些策略参考用户提供的 [Unity 物理性能指南](https://unity.com/how-to/enhanced-physics-performance-smooth-gameplay) 和 [碰撞检测模式说明](https://docs.unity.com/en-us/engine/6000.0/manual/physics-section/physics-overview/physics-optimization/cpu/rigidbody-collision-modes)，并在本项目 Unity 2022.3 中实际构建验证。

原始逐帧数据与汇总位于 `Performance/`。在运行版上使用 `--benchmark-dir` 加输出目录可以重新采样；入口实现为 `Assets/Scripts/PerformanceProbe.cs`。样本同时包含轻损、局部和整体破坏阶段，不含预计算路径初始化时间。
